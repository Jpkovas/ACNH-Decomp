# Coordinated work and first epoch-v2 startup observation

Eight separate local threads and three cloud threads now contribute to the
same full native Windows reconstruction objective. Local ownership covers
save transactions, GPU previews, flag writers, schema lookup, original audio
routines, tutorial/save planning, delivery review and memory/startup integration.
Cloud work uses own interfaces and synthetic data only. Proprietary dumps,
keys, firmware, assets, captures and lifted source remain local and private.

Every worker must deliver hashes, commands, retained failures, modeled/original
dependency distinctions, integration steps and limits. Independent review and
coordinator-controlled real execution precede default promotion. See
[the delivery contract](DELIVERY-TEMPLATE.md) and [the board](BOARD.md).
The coordinator has a 15-minute heartbeat to inspect progress and deliveries;
only the coordinator admits game processes under an exact timing lease.

The first controlled epoch-v2 startup reached the initial dialogue with
nonzero PCM and exited naturally with code 0. The requested duration was
180 seconds; observed process wait was 181.019 seconds, including exit
observation. Complete harness/postprocessing took 186.211 seconds. Its final
JSON records the original process handle, PID 31320, confirmed absence,
unchanged artifacts, restored environment and release of the same lease.
The native audio capture contains 176.54 seconds, with 12,528,054 nonzero
channel samples and zero clipped samples. These signal metrics do not establish
perceptual accuracy.

Exact runtime/module hashes, common controls against the earlier nine/fourteen
entry runs, private capture hashes and explicit visual assessment are in
[the aggregate proof](../../metadata/windows/1.0.0/startup-epoch-team-validation.json).
The [reporting script](../../scripts/report_team_epoch_startup.py) verifies the
actual terminal/audio/capture artifacts locally before writing that aggregate.
The [candidate integration report](epoch-integration/REPORT.md) documents
actual-module gates, 13 runtime CTests, three own loader scenarios and their
remaining dependencies. Candidate and preserved default binaries are separate.

This is one candidate execution. Runtime and module provider changed together;
the comparison does not isolate a performance cause. Repeat startup, normal
input/tutorial, title GPU scenes, audio correctness and real save/reload remain
pending. The default was not promoted. Integrated coverage remains 14 complete
bodies / 2,212 of 44,815,680 bytes, approximately 0.0049357725%. No cloud,
infrastructure or isolated-candidate bytes were added.

The next coordinated work is to validate the connected player group in the
actual module, integrate it into a separate candidate with exact loader/API
binding, repeat controlled startup, then validate GPU previews and proceed
through the tutorial to a real save and fresh-process reload. Automatic lifting
and original ARM64 interpretation remain dependencies; the decompilation goal
is active and incomplete. This documentation milestone does not publish a new
build or claim clean-build reproducibility.
