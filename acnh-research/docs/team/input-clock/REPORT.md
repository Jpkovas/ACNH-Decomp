## Implementation and clock contract

The private baseline is the exact CRLF `vendor/ScarletNX/runtime/platform/unattended.c`, SHA-256 `c0907214fea84373f3577b798412d150b14f3a68e837967170033c2cc1d677e6`. The private patched file is `fd15de6c7c29bf92753cbc9b40c014ad907c9d6f4eba8b090cb0b10152819dac`; its LF unified diff is `826416e57cde8b399cbe71c1499e17276c775b662b5fb0b121189a8483d60fd3`. `prepare_patch.py` regenerates both only from the pinned baseline and copies the upstream license/NOTICE files.

`SNX_INPUT_CLOCK_TRACE` is optional. At the existing `unattended_start`, the patch records the already assigned `g_start`, QPC frequency, PID, thread ID and exact process-creation FILETIME. It does not take a second `plat_ns` sample. The file is opened with the native wide environment/path APIs and `CREATE_NEW`; an existing filename or failed marker invalidates evidence rather than reusing a previous run. A sequential second start produces another marker, which the helper rejects.

Immediately before the existing `unattended_buttons` return, enabled tracing emits the first observation, including zero, then only changed synthetic masks. Each row records the original calculated integer `elapsed_ms`, captured start, PID/TID and per-thread sequence. Diagnostic TLS owns previous-mask/generation/sequence state. The trace handle remains immutable and open until process exit. Each bounded row uses one checked synchronous append `WriteFile`; failed writes disable further attempts for that thread. The patch preserves `errno` and `GetLastError`, including unchanged/failed paths. It never calls the logger, reads `g_frames`, acquires an application mutex, changes input/script state or accesses guest memory. No sleep, title-specific rule or timing adjustment is added.

When tracing is disabled, source fixtures show identical parsing, button outputs, start/restart/expiry behavior, stub side effects, errors and `plat_ns` call counts. This is semantic comparison, not byte-identical code or a wall-time identity claim. Enabled synchronous file I/O can stall an input poll. Partial or missing records are not proof of a stable mask, and ordinary successful writes do not prove crash durability.

The current caller graph starts unattended input during backend `video_init`, before renderer/window startup and guest main. `g_start` therefore includes that remaining startup time. Process creation UTC, launch time and screenshot index are identity/progress evidence, not this input clock. Current normal polling, file reload and configuration are main-thread owned. The patch does not make concurrent start, reload or configuration changes safe. Immutable-input tests exercised 16 readers; TLS does not give a global ordering across threads. Existing mixed `g_frames` accesses, lazy frequency initialization and logger-origin initialization were audited but not repaired here. The actual integrated runtime must recheck native TLS linkage and startup ownership with its own compiler flags.

Windows `plat_ns` is pinned at SHA-256 `ecef0b8183dafb4660522c809b537c402a08566a7a63e9c00306f29359fc2d5a` and uses:

```c
(u64)((double)ticks * 1e9 / (double)frequency)
```

The helper uses the same binary64 operation order followed by truncation, not integer rational division. PowerShell delegates all clock arithmetic to Python because a PowerShell double-to-integer cast can round. There are real differences: `(ticks=2^53+1, frequency=1e9)` converts to `2^53`, whereas exact integer division gives `2^53+1`; `(ticks=1, frequency=600000000)` truncates to 1 rather than a rounded 2. A rationally evaluated conservative binary64 bound and a separate QPC tick bound accompany each live sample. These bound numerical conversion, not input delivery latency. QPC is shared across processes on the same current Windows system/VM; a cloud worker's QPC cannot schedule this process. See the read-only private QPC audit and [Microsoft's QPC guidance](https://learn.microsoft.com/en-us/windows/win32/sysinfo/acquiring-high-resolution-time-stamps).

## Admission and one-pulse protocol

The frozen harness writes its terminal JSON only after the runtime terminates. The helper therefore creates a separate, explicit `coordinator-live-input-admission` receipt while the process is alive. `admit` validates the actual runtime path/hash, original process handle, PID, exact creation time, complete unique marker, QPC frequency and canonical prefix/trace/input paths. OS process APIs query identity and time only; the helper has no process-memory read/write API. Production paths are restricted to private Windows inputs/logs and approved runtime locations; own synthetic paths require explicit `-Synthetic`. Reparse ancestors are rejected before resolution.

The coordinator must independently attest the actual `--script_file` binding, effective default press length, disabled legacy `press`, exclusive ownership of the input file and frozen configuration. The receipt records those attestations; it cannot discover all of them from the process identity APIs. No terminal/gameplay claim follows from admission. The coordinator must also verify the complete proposed pulse fits the actual run's stop budget; this helper does not derive that budget from process UTC or screenshots.

Use a fresh private prefix and absent trace path. Set the environment before the coordinator launches its separate diagnostic runtime, and restore it afterward. The marker path must be `<prefix>.input-clock.trace`; the live file must be `<prefix>.inputs.csv`. The receipt path must be `<prefix>.input-clock-admission.json`. For example, after the coordinator has obtained the actual process identity and effective configuration:

```powershell
$clockScript = 'D:/ACNH_Decomp/acnh-research/scripts/input_clock_team_candidate.ps1'
& $clockScript -Mode admit -Report ($prefix + '.input-clock-admission.json') -Runtime $runtime -RuntimeSha256 $runtimeSha -ProcessId $runtimePid -StartUtc $runtimeStartUtc -OwnerThread $owner -Prefix $prefix -Trace ($prefix + '.input-clock.trace') -DefaultPressMs $effectivePressLength -LegacyPressDisabled
& $clockScript -Mode elapsed -Report ($prefix + '.input-clock-admission.json') -ProcessId $runtimePid -StartUtc $runtimeStartUtc -RuntimeSha256 $runtimeSha -Prefix $prefix -Trace ($prefix + '.input-clock.trace')
& $clockScript -Mode prepare -Report ($prefix + '.input-clock-admission.json') -ProcessId $runtimePid -StartUtc $runtimeStartUtc -RuntimeSha256 $runtimeSha -Prefix $prefix -Trace ($prefix + '.input-clock.trace') -LeadMs 2000 -DurationMs 1500 -Mask 1
```

`prepare` defaults to a dry run. `-Publish` authorizes exactly one future normal pulse. Repeating the command creates a different batch/time; do not treat a second invocation as confirmation of the first. Every batch archives the exact previous input and candidate bytes before publication. Any active or future existing press is rejected; only past entries are retained. Publication requires strict integer duration 1..10000 ms, lead 1000..60000 ms, strict Boolean permission and a normal nonzero mask at most `0xFFFFFF`. It rechecks the original live process, source input and at least 500 ms remaining margin after temporary-file flush/fsync, immediately before replacement. A late deadline rejects without automatic rescheduling. Comparing then replacing is not atomic compare-and-swap: the coordinator's exclusive input ownership remains essential. Hostile concurrent path substitution is outside this control contract.

If replacement succeeds and later bookkeeping fails, the helper returns `scheduled=true`, `published=true`, `scheduled-bookkeeping-failed` and the archive path. Do not retry or report unscheduled. Generic rejection uses `scheduled=null` to avoid denying an existing published pulse; observing a known committed batch retains `scheduled=true`. A rejected read-only `elapsed`/`observe`, or `prepare` proven rejected before publication, may be retried after a partial trace completes. Never retry publication on an uncertain or committed result. A malformed JSON request or PowerShell parameter rejection may produce no structured receipt; it does not authorize input.

`observe` needs only the published archive via `-Batch`. It validates archived marker/path identity and records per-thread observed press and zero release rows; it does not require a live process or consume the other current-PID/path arguments. This is an archived host-observation check. The script-file check is throttled to intervals of at least 100 ms, with additional frontend/OS stalls; this is not a maximum delivery latency. Normal frontend polling is approximately 60 Hz. `scheduled`, `host_mask_observed` and guest consumption are separate evidence levels. SDL merges physical inputs afterward and HID may add stick directions. This task never claims guest/Npad consumption. Analog movement bits 40..47 are deliberately excluded from this helper; the coordinator can use its existing `tutorial_live_v2` movement sender with a bound derived from this same marker after its own validation.

## Integration gates, remaining limits and licensing

The coordinator must verify the original unattended source hash and copy the exact private patched bytes into its separate runtime candidate. Standard `git apply` rejects the LF diff against raw CRLF; `--ignore-space-change` applies to an owned scratch copy but yields mixed newlines. The scratch application was normalized and compared to the exact patched source; use the pinned CRLF file or normalize then require the pinned SHA before compiling. No integration into the shared vendor source occurred here.

Before any real launch: require independent review, exact candidate source/runtime/DLL hashes, separate backend/config identity, native TLS import/symbol gate with actual flags, normal startup ownership, disabled effective legacy press, fresh marker/admission and exclusively coordinated input file. Preserve existing save/WAV evidence, bind the lease through the coordinator and serialize runtime tests. The helper does not acquire or release the timing lease. Gameplay/tutorial and genuine save/reload require later coordinator tests, with guest consumption proved at the actual Npad path rather than inferred from host rows.

No known source blocker remains after the reviewed corrections. Unexecuted cases include concurrent start/reload, runtime/compiler flag variants, trace failure on every Windows filesystem, hostile concurrent reparse replacement, suspend/restore/VM migration, memory exhaustion, all malformed requests and actual integrated guest/backend behavior. Failed/partial trace snapshots fail closed without input. Actual synchronous publication/I/O can block after the final sample; only observation proves host timing. No guarantee of nanosecond delivery or absence of diagnostic timing perturbation is made.
